Camera-pose viewers

How the task viewers are built: per-demo camera trajectories from Aria MPS, all demos registered into one shared room frame, plus (for cup_plate_02) the pose of the robot test rig's RealSense camera placed into the same frame.

cup_plate_02 → serve_bread → water_flowers →

Where the poses come from

  1. For every demo, MPS gives the closed-loop device trajectory T_world_device(t); composing with the online calibration (device → RGB camera) yields the RGB camera pose per frame.
  2. Each demo lives in its own gravity-aligned world. The demo with the lowest index (000) is the reference; every other demo is registered to it with a trimmed 4-DoF ICP (yaw + translation — gravity already fixes roll/pitch) run on the semidense room clouds.
  3. Trajectories, frustums, and the room cloud are baked into one self-contained HTML file (WebGL renderer with a Canvas-2D fallback, no dependencies).

Placing the RealSense test camera (red frustum)

The robot test rig is a different site with no visual overlap, so the bridge is a task frame built identically on both sides from the task objects:

  • Origin = plate center — the plate stayed fixed during collection (the cup was varied).
  • +Z = gravity up (MPS world on the demo side; fitted table plane on the rig side).
  • +X = horizontal plate→cup direction. On the demo side it is averaged over all 64 demos, so the per-demo cup variation cancels; on the rig side it comes from depth-deprojected cup/plate centers.

Composing rig→task-frame with task-frame→viewer-world places the RealSense pose in the viewer. A synthetic check with a known camera recovers it to ~2 mm / 0.01°; the real placement lands in-distribution with the demo head poses (44° elevation vs 48°±4° across demos, ~3° azimuth offset).

Viewer features

  • Slider steps through demos; a per-demo frustum-count control subsamples the trajectory (1…all).
  • Blue = camera frustums, orange = head path, red = RealSense test camera with an XYZ triad (cup_plate_02 only).
  • Drag = rotate, scroll = zoom, shift-drag or right-drag = pan.

Built with extract_multi.py (packs poses + clouds per task into one npz) and make_web_viewer.py (bakes the HTML; --extra-cams draws the test camera); place_test_cam.py computes the test-camera pose from per-demo training_data.json files plus the rig's depth measurements. Data: Aria MPS SLAM (closed-loop trajectories, online calibration, semidense point clouds).
