Pipeline

How it works

  1. Hands: Aria MPS hand tracking gives 21 3D landmarks per hand per frame, already in the MPS world.
  2. Objects: Grounding-DINO + SAM 2 segment each object, keypoints are selected on the mask, CoTracker follows them in 2D, and multi-view triangulation against the SLAM trajectory lifts them to 3D. Each object's points are stored once in its local frame and re-posed every frame by the latched object pose T_obj_to_world.
  3. Static anchor: the anchor object (the cup) is deliberately frozen at its pre-grasp pose in the observation — the policy sees where the interaction started, not the object riding the hand. This is why the cup points stop moving after the grasp in the viewer: by design, and inference reproduces exactly the same convention.
  4. Features: every point becomes an 8-vector — normalized xyz in the episode reference frame (camera at frame 0), a 4-way entity one-hot (left hand / right hand / anchor object / other object), and the grasp state of its hand (−1 for object points). Farthest-point sampling fixes N = 96 points per frame.
  5. Encoder: a shared MLP embeds each point and masked per-entity max-pooling produces 5 tokens (global + one per entity) — the policy's entire observation context.

Viewer features

  • Slider / play steps through frames; colors encode entity (hands, anchor, other objects).
  • Hand trail, grasp indicator, fitted table grid, and the frame-0 camera frustum for orientation.
  • Deep-link to a frame with #f=N.

Built with preprocess/PointCloudGen.py (writes per-frame pcd.npz next to training_data.json), utils/pcd.py (shared geometry ops), and the viewer pair extract_pcd_seq.py + make_pcd_viewer.py. Training consumes the same files via obs_mode=pointcloud in the dataloader.
